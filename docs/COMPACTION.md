# 上下文压缩：设计与使用

tree-chat 把一次成功的 DSH 压缩保存为独立的「上下文压缩」节点。它记录实际生效的摘要及对应历史边界，而不是把当前摘要套用到所有旧节点。

## 操作与结果

在 DSH 聊天输入框执行 `/compact`，成功后节点会出现在当前枝上。自动压缩也会记录；自动压缩发生在一轮内部时，等待这一轮完整结束再提交节点，保留完整的工具调用和结果。

| 操作 | 后续请求的上下文 |
| --- | --- |
| 直接在当前压缩后的聊天中继续 | 沿用 DSH 已生效的压缩上下文 |
| 从压缩节点新建分支 | 对应摘要，加上未被替换的轮次 |
| 从压缩之前的历史节点开枝 | 截止该节点的原文，不借用后来生成的摘要 |
| 删除或重新连接压缩所依赖的历史 | 旧节点显示「已失效」，重建时按修改后的原文组成上下文 |
| 在压缩节点菜单选择「移除压缩，使用原文」 | 移除该逻辑边界，按当前保留的原文重建；可撤销 |
| 双击压缩节点 | 跳到 DSH 原生聊天的对应压缩记录，可查看原生摘要 |

例如：`1 → 2 → 3 → 4 → 压缩 A`，其中 A 替代 1、2。选择 A 后使用 `摘要 A + 3 + 4`；从 2 开枝使用 `1 + 2`。若删掉 2，A 依赖的路径已经变化，后续改用 `1 + 3 + 4`，不会让摘要把 2 的内容带回来。

移动位置、重命名、集合展开和折叠保持节点关系不变，不会令摘要失效。修改更早的压缩节点也可能使后续摘要失效；连续压缩按各自的依赖链独立校验。

查看旧的原生会话时，如果它还带有已经失效的上下文，会显示「上下文待应用」。点击「应用当前路径」后再继续。后台同样会阻止旧会话直接使用失效摘要。

## 为什么可以实现

已验证的 DSH 原生日志保留以下记录：

1. `compaction/start`：压缩事务开始。
2. `compaction/summary`：摘要正文、被覆盖的历史范围和来源。
3. 带有 `surfaceOp: replace` 的检查点消息：实际进入模型上下文的摘要。
4. `compaction/end`：事务结束。

手动压缩可以发生在普通聊天轮次之外，因此仅检查 `turn/end` 会漏掉它。tree-chat 识别完整压缩事务并监听结束事件，侧栏关闭、尚未发送下一条消息时也能记录；开启项目同步的树会跟进保存。

取消、失败或未完成的事务不生成成功节点。压缩进行中，开枝、上下文结构编辑、导出和项目写入需要等待完成；画布浏览和位置调整仍可使用。

## 上下文重建原则

1. 根据路径上实际选择的节点，读取各原生来源截止相应位置的日志。历史分支不会受后来压缩或裁剪影响。
2. 从原始来源恢复消息和工具配对，给消息保留稳定的来源身份。
3. 到达有效压缩节点时，核对完整前缀、事务身份、替换范围及消息来源，再原位替换被覆盖部分。
4. 摘要跨越多个原生会话时，通过消息身份及原始来源集合识别范围；后一次压缩可以替代前一次摘要。
5. 路径签名改变时，不使用旧摘要。无法证明范围一致的记录停止应用，保留原生数据，避免猜测上下文。
6. 为结果建立新的原生轮次和步骤，并通过 DSH 原生重放校验后创建分支。

`prefixKey` 保存压缩时的祖先节点路径。它不依赖标题和坐标，因此布局或名称变化不会误判。替换校验既检查被摘要覆盖的消息，也检查完整前缀，防止旧导出丢失重建标记后，把其他枝的内容拼进摘要之前。

## 旧树与迁移

- 旧树可从原生日志补入压缩节点。补入集合内部时保持集合连通，不把压缩前的侧枝改接到压缩后。
- 旧版已经将摘要复制进新分支、原压缩事件仍在旧来源时，会追溯原始事务并恢复边界。无法证明与现有路径一致时，标为失效并要求重建。
- 删除记录使用事务身份保存，避免被后台轮询、旧原生分枝或迁移恢复重新添加；显式撤销仍可恢复节点。
- 项目同步和自包含对话文件都保留检查点、原文、摘要、来源关系和待重建状态。身份迁移同时转换依赖路径；导入后先修复当前会话的失效上下文，再交给用户继续聊天。
- Markdown 阅读版分别列出原始轮次和压缩摘要，不因后来压缩而抹去早期文字；完整原生事件仍在会话日志中。

这套机制依赖原生日志仍保留相应的原文和事务记录。外部删除或损坏原始来源后，无法安全恢复旧枝时会拒绝重建，不凭空补齐历史。已经含有压缩节点的树请继续使用 1.3.0 或更新版本。
