# 项目记录格式 v1

tree-chat 1.2 引入可选的 `tree-chat-project` 格式。它保存可恢复的数据和阅读版文档，不改变 DSH 的原生持久化后端，也不运行 Git 命令。

## 文件与身份

每棵树保存到 `.tree-chat/trees/<tree-id>/`。`tree-id` 为首次开启同步时生成的稳定标识；同一项目可以保存多棵树。

| 文件 | 内容 |
| --- | --- |
| `manifest.json` | `format`、`version`、树标识、标题、节点数、图/文档哈希、会话索引和附件索引，以及整个清单的快照哈希 |
| `tree.json` | 沿用图 schemaVersion 1，包含节点、来源、绑定、集合、空枝、活动位置；不含本机撤销/重做历史，revision 规范为 0 |
| `conversation.md` | 按节点展示输入、回复和工具内容的阅读版，不能单独用于恢复 |
| `sessions/<session-id>.jsonl` | 第一行为 `tree-chat-session` version 1 包装头，之后每行一个完整原生 V4 事件，保留 seq、时间与 surface 元数据 |
| `assets/<sha256>` | 内容寻址的图片和文件二进制；索引保留原生引用、种类、字节数与内容哈希 |

本机配置记录“项目会话身份 → 本机会话身份”的映射。新机器恢复会话时总是生成新的本机 UUID；再次同步时转换回稳定项目身份。节点中的会话前缀、pending 节点、集合成员、来源、路径绑定和空枝返回目标会一起转换，避免同名会话覆盖或迁移后整棵树换号。

首行包装不是可直接复制到 DSH 数据库的原生日志文件。需要通过 tree-chat 的读取入口恢复，因为工作目录、身份、权限、模型与媒体引用均有本地化处理。

## 目录、权限与附件

- 项目会话头和 `working-directory/change` 中的目录保存为项目相对路径。项目外目录归一为项目根；读取时拒绝绝对路径和 `..`，不让旧机器目录控制新会话的未来执行位置。
- 历史对话、工具参数及结果是记录本身，文本中的旧路径保持原意。原生运行时会为下一次请求生成当前本机环境快照。
- 原始执行策略事件保存在项目日志中供审阅，导入时历史 preset/sandbox/approval 改为 workspace-write/ask，然后由 DSH 原生服务应用当前发起读取的会话权限。模型和智能体预设也取当前本机配置，不从项目开启 Auto、不恢复旧 provider replayState。
- 图片和文件通过 DSH 原生附件 API 读取、校验和恢复，不绕过媒体后端直接写其私有目录。原生图片归一化可能重写引用；恢复后的事件使用新引用。没有挂载附件服务或附件缺失时拒绝完整同步/恢复，不悄悄丢弃。
- 不包含模型凭证、整个仓库、网页内容的外部依赖，以及未被树引用的子任务会话。工具输出里出现过的内容属于对话记录，会随日志保存。

## 更新与冲突

1. 本机树仍为编辑工作副本。关闭同步时完全不写项目；开启后监听树保存与完成轮次，合并短时间内的多次变更。
2. 同树生成中等待，不导出半轮；对已完成的后台分支也同步，界面隐藏不影响。
3. 同步前核对上次快照身份，并校验现有图、会话、文档、附件；内容不变不重写。
4. 使用 `.tree-chat/.locks/<tree-id>/` 防止两个进程同时发布同一记录。锁不按时间猜测抢占。
5. 新文件先写入 `.tree-chat/.staging/`，完整后替换记录目录；替换失败尝试恢复旧目录。普通成功路径清理临时内容。Git 只需忽略 `.staging/` 和 `.locks/`，无需忽略正式记录。
6. Git 切换或外部修改与上次快照不同，则暂停自动写入。读取项目版会创建独立本机副本；另存副本会创建新 tree-id，不覆盖冲突记录。

清单快照由不带 `snapshot` 字段的漂亮 JSON（2 空格、末尾 LF）计算 SHA-256。图、文档、JSONL 和二进制分别按实际字节计算哈希。复制记录必须携带清单引用的所有文件；不建议手工合并原生事件序号。额外笔记应放在受管记录目录外，插件遇到未登记文件会拒绝替换。

## 恢复与兼容

读取先检查格式、大小、哈希、来源范围、路径及原生 Session 解释，再恢复附件和新会话。源会话不被替换。界面打开恢复后的原生聊天，可以继续发送消息；同步默认关闭，再开启时沿用导入记录身份。

当前不做多人同时编辑同一树的自动 CRDT 合并；通过 Git 选定版本、读取为新对话或另存副本处理分歧。格式版本未知时拒绝读取，保留文件供后续迁移器处理。

文件层、可移植格式和宿主协调分别位于 `project-files.js`、`project-format.js`、`project-sync.js`，后续存储后端与格式迁移可独立扩展。实际兼容范围与测试结果见 [验证记录](VALIDATION.md)。
